# USBL-RS — реконструкция USB-загрузчика Huawei E3272s-153 на Rust

Полная переписанная на Rust версия загрузчика **USBL (burn-режим)** модема
**Huawei E3272s-153** (Balong V7R1, HiSilicon HI6920, ARM Cortex-A9),
построенная по реконструкции [s1oappp/ANUS](https://github.com/s1oappp/ANUS)
(`E3272s-153_USBL` — декомпиляция и документация `usblsafe-327x.bin`,
VxWorks 6.8, прошивка 21.431.99.07.00).

**Итог сборки:** `usblsafe-327x-rs.bin` — образ того же формата, того же
размера (1 754 444 байта) и с байт-в-байт идентичным заголовком bootrom,
что и оригинал.

## Выбранная трактовка совместимости: «интерфейсы + данные»

Байт-в-байт идентичный машинный код на Rust невозможен (это даёт только
ассемблерный путь `rebuild/` исходного репозитория). Совместимость здесь —
на уровне контрактов:

| Слой | Совместимость |
|---|---|
| Формат образа | заголовок 84 байта **байт-в-байт из оригинала** (поля +0x28/+0x2C/+0x38/+0x3C/+0x40 валидны, т.к. секции добиваются до исходных размеров); общий размер 1 754 444; стаб @0x2FFE4000 (вход), тело @0x30004000 |
| Стаб DDR | та же последовательность из 50 MMIO-записей (адрес+значение, по порядку) — см. `tools/verify.py`, проверка 50/50 |
| Консоль | UART PL011 @0x90007000, 115200 8N1, клок 48 МГц (docs/08) |
| USB | DWC OTG HS @0x900C0000, VID 0x12D1, PID **0x1C05**, 3× CDC-ACM «MDM+PCUI+DIAG», строки «HUAWEI Mobile»/«HUAWEI Technology» |
| AT-интерфейс | обе таблицы оригинала (уровень 1 — 11 команд с `\r`, уровень 2 — 16 записей), ответы `\r\nOK\r\n`/`\r\nERROR\r\n`, форматы `^HWNATQRY:%d`, FLASHINFO — байт-в-байт из образа |
| DLOAD-протокол | HDLC (PPP FCS-16, таблица из образа, магия 0xF0B8, буфер 0x2200), пакеты 0x41/0x42/0x43/0x0A/0x0C/0x3A/0x45/0x46/0x4B/0xFB, big-endian поля, статические кадры ответов байт-в-байт, кадры 'E'/'F'/'K' с оригинальной семантикой (включая сдвиг-на-1 у 'K') |
| Флеш | ptable (0x400 байт из образа, 17 разделов, маркеры T/pTableTail), A/B по seq/validity, запись в старую копию, integrality |
| Данные | FCS-таблица, ptable, huaweiProduct (17 записей × 0x34 + строковый пул, 1360 байт), маркерные слова стаба — всё встроено из образа байт-в-байт |
| Защита | слово-ловушка `0x2ffffffc == 0x98765432`, при несовпадении — `nand_erase_all()` (как в оригинале) |

## Модель исполнения

`no_std`, голое железо: VxWorks 6.8 заменён детерминированным главным
циклом (poll USB + консоль + кормление WDT) с IRQ-диспетчером через
контроллер прерываний @0x08000000 (IAR +0x10C / EOI +0x110 — карта
восстановлена из `armGicCtlInit`/`FUN_30007f84`). Порядок запуска
повторяет `usrRoot → usrAppInit` оригинала (docs/01 §6).

## Структура

```
usbl-rs/
├── build.sh                  # сборка: cargo (armv7a-none-eabi) + pack.py
├── link.x                    # карта памяти: IRAM 0x2FFE4000 / SDRAM 0x30004000
├── data/                     # блоки, извлечённые из оригинала байт-в-байт
│   ├── header.bin            #   84 байта — заголовок bootrom
│   ├── fcs16_table.bin       #  512 байт — таблица FCS-16 @0x3014C108
│   ├── ptable.bin            # 1024 байта — дефолтная ptable @0x3018000C
│   ├── product_table.bin     # 1360 байт — huaweiProduct + строковый пул
│   └── usb_burn_profile.bin, usb_templates.bin
├── src/
│   ├── main.rs               # главный цикл (= usrAppInit), паника
│   ├── start.rs              # векторы ARM + sysInit (CP15, кэши, .bss, стек)
│   ├── stub.rs               # стаб DDR в IRAM (global_asm, 50 записей как в оригинале)
│   ├── mmio.rs               # volatile-примитивы
│   ├── console.rs            # PL011 @0x90007000
│   ├── vic.rs                # контроллер прерываний @0x08000000 (160 линий)
│   ├── wdt.rs                # SP805 @0x90001000 (магия 0x1ACCE551)
│   ├── hdlc.rs               # Om_HdlcDecap/Encap + FCS-16
│   ├── at.rs                 # ATCommandProcess/Handle
│   ├── dload.rs              # FUN_30080798 + dloadUSBSendPro
│   ├── ptable.rs             # A/B, seq/validity, integrality
│   ├── nand.rs               # NANDC @0x900A4000 (магия 0x19840815)
│   ├── product.rs, version.rs, safety.rs
│   └── usb/                  # dwc.rs (DWC OTG), ch9.rs, desc.rs (3× CDC-ACM)
└── tools/
    ├── pack.py               # ELF → .bin (заголовок + стаб + тело, добивка)
    ├── verify.py             # 14 проверок против оригинала (все OK)
    ├── proto_test.py         # протокольный тест кадров/пакетов
    └── extract_data.py       # извлечение блоков из оригинала (воспроизводимость)
```

## Сборка

```bash
rustup target add armv7a-none-eabi    # ARMv7-A, ARM-режим, soft-float
./build.sh                            # → usblsafe-327x-rs.bin (1 754 444 байта)
python3 tools/verify.py               # сверка с оригиналом
python3 tools/proto_test.py           # протокольные кадры
```

## Честные ограничения (как и в исходной реконструкции)

1. **Регистровая карта NANDC V2** внутри окна 0xB0 @0x900A4000 частично
   помечена `[ПРОВЕРИТЬ]` — в репозитории-источнике карта не восстановлена
   (docs/06 §8); каркас (магия, erase/write/read/verify/bad-scan, ptable)
   соответствует реконструированному потоку.
2. **Таймер sysClk** заменён программными задержками — MMIO-база таймера
   в образе не видна (BSS), точный тик требует проверки на устройстве.
3. **NV-память** (IMEI/версия ПО из NV) деградирует до дефолтов — NV-слой
   вне объёма порта (как отмечено и в самом ANUS).
4. **DWC OTG** работает в FIFO-режиме (оригинал — DMA): на уровне
   проводного протокола эквивалентно.

## ⚠️ Осторожно с прошивкой

Всё как в `docs/10_MODIFICATION_GUIDE.md` исходного репозитория:
раздел **BootLoad не имеет A/B-резерва** — прошивать только при
подтверждённом bootrom-канале восстановления (тестпоинт). Перед
экспериментами: полный дамп NAND; помнить про `nand_erase_all` при
несовпадении слова 0x2ffffffc. Прошивка принадлежит Huawei — образ
предназначен для исследования собственного устройства.
